바이브 코딩 제작 방법

코드를 몰라도 괜찮습니다. AI와 충분히 대화하며 수업에 딱 맞는 교육용 웹앱을 직접 만들고, 학생들과 공유하는 두 가지 방법을 단계별로 안내합니다.

01

바로 링크로 만들어 사용하기

AI 채팅창 안에서 웹앱을 만들고, 생성된 링크를 그대로 학생에게 공유합니다.

Intro

바이브 코딩이 뭔가요?

코드를 한 줄씩 직접 타이핑하는 대신, "이런 것을 만들고 싶어"라고 AI에게 말로 설명하고 AI가 코드를 만들게 하는 방식입니다. 우리는 '무엇을 만들지'와 '잘 만들어졌는지'에 집중하고, '어떻게 코드로 쓰는지'는 AI에게 맡깁니다.

🧑‍🏫 교사에게 좋은 이유

시중 자료가 우리 반 수업 흐름과 딱 맞는 경우는 드뭅니다. 판의 경계 시뮬레이션, 달의 위상 퀴즈처럼 내 수업에 맞는 도구를 그날 바로 만들 수 있습니다.

🧩 필요한 것

AI 채팅 계정(Gemini·ChatGPT·Claude 중 하나)과 만들고 싶은 것에 대한 구체적인 생각이면 충분합니다. 방법 2는 GitHub·Vercel 계정이 추가로 필요합니다.

💡 성공의 열쇠

좋은 결과물은 좋은 코드가 아니라 좋은 대화에서 나옵니다. 바로 코드를 시키지 말고 먼저 대화로 기획을 구체화하세요. 아래 핵심 원칙에서 자세히 다룹니다.

Key Principle

핵심 원칙 · 코드보다 대화가 먼저입니다

어떤 방법을 쓰든 가장 중요한 단계입니다. AI에게 첫 메시지를 보낼 때 이 한 문장을 꼭 넣으세요.

첫 메시지에 꼭 넣을 말
바로 코드를 짜지 말고, 먼저 나와 충분히 대화하면서 무엇을 만들지 구체화한 다음에 코드를 짜줘
AI가 질문을 던지고, 내가 답하면서 기획이 저절로 구체화됩니다.

😵 바로 코드를 시키면

  • AI가 모호한 부분을 자기 마음대로 채웁니다. (대상 학년, 용어, 화면 구성…)
  • 결과물을 보고 나서야 "이게 아닌데"를 깨닫습니다.
  • 고치는 요청을 반복하다 코드가 꼬이고, 처음부터 다시 만들게 됩니다.

😊 대화로 먼저 구체화하면

  • AI가 내가 미처 생각 못한 것을 질문해 줍니다. (스마트폰 지원? 퀴즈 채점?)
  • 내 머릿속 그림이 글로 정리되어, 나중에 수정 요청도 쉬워집니다.
  • 한 번에 원하는 것에 가까운 결과가 나와 시간이 절약됩니다.

대화로 구체화하는 3단계

1단계

대화를 요청한다

만들고 싶은 것을 한두 문장으로 말하고, "바로 코드를 짜지 말고 먼저 질문해 줘"라고 덧붙입니다.

2단계

AI의 질문에 답한다

대상 학년, 학습 목표, 기능, 화면, 사용 환경을 정합니다. 모르면 "네가 추천해 줘"라고 해도 됩니다.

3단계

요약을 확인하고 코드를 요청한다

AI가 정리한 기획 요약을 읽고 빠진 것을 보충한 뒤, "좋아, 이제 코드를 짜줘"라고 말합니다.

예시 대화 · 판의 경계 탐험 웹앱

실제로 이렇게 흘러갑니다. 파란색은 선생님, 흰색은 AI입니다.

선생님판의 경계를 탐험하는 교육용 웹앱을 만들고 싶어. 바로 코드를 짜지 말고, 먼저 나에게 질문하면서 무엇을 만들지 충분히 구체화한 다음에 코드를 짜줘.
AI좋습니다! 코드를 짜기 전에 몇 가지 여쭤볼게요.
  1. 대상 학년과 학생들의 사전 지식은 어느 정도인가요?
  2. 발산·수렴·보존 경계 세 가지를 모두 다루나요? 수렴 경계는 해양-대륙, 대륙-대륙 등으로 나눌까요?
  3. 학생이 어떻게 상호작용하길 원하시나요? (버튼 클릭, 드래그, 슬라이더 등)
  4. 애니메이션이 필요한가요, 정지 그림으로 충분한가요?
  5. 마지막에 퀴즈나 정리 활동을 넣을까요?
  6. 주로 어떤 기기에서 사용하나요? (교실 TV, 태블릿, 스마트폰)
선생님1. 중학교 2학년, 판 구조론 기본 개념은 배운 상태야. 2. 세 가지 다 다루되 수렴 경계는 해양-대륙만. 3. 경계 종류 버튼을 누르면 단면도가 바뀌면 좋겠어. 4. 판이 움직이는 간단한 애니메이션이 있으면 좋겠어. 5. 마지막에 3문제 퀴즈, 정답 여부를 바로 알려줘. 6. 태블릿과 스마트폰에서도 잘 보이게. 전부 한국어로.
AI정리하면 이렇습니다.
  • 대상: 중2, 판 구조론 기초 학습 후
  • 화면: 상단에 발산·수렴(해양-대륙)·보존 버튼 3개, 아래에 단면도 애니메이션과 설명
  • 내용: 각 경계의 판 이동 방향, 대표 지형(해령·해구·변환단층), 예시 지역
  • 퀴즈: 3문항 객관식, 즉시 채점
  • 환경: 반응형(태블릿·스마트폰), 한국어, HTML 파일 1개
추가로 예시 지역에 실제 지명(예: 동아프리카 열곡대, 안데스 산맥, 산안드레아스 단층)을 넣을까요? 이대로 진행할까요?
선생님실제 지명 넣어줘. 좋아, 이제 코드를 짜줘. HTML 파일 하나로 만들어줘.

대화에서 꼭 정해야 할 것 체크리스트

  • 대상 · 학년, 사전 지식 수준
  • 학습 목표 · 이 웹앱을 쓰고 나면 학생이 무엇을 할 수 있어야 하는가
  • 핵심 기능 · 시뮬레이션, 퀴즈, 그래프, 카드 뒤집기 등 딱 필요한 것만
  • 화면 구성 · 어디에 무엇이 보이는지 (말로 설명하거나 손그림 사진 첨부)
  • 사용 환경 · 교실 TV, 태블릿, 스마트폰 / 인터넷 여부
  • 과학적 정확도 · 교과서 용어와 표기를 따르도록 요청 (예: "2015 개정 교육과정 중학교 과학 용어 사용")
  • 형식 · "HTML 파일 하나로", "외부 로그인 없이", "한국어로"
Method 01

방법 1 · 채팅으로 바로 만들어 링크로 공유하기

Gemini, ChatGPT, Claude는 채팅창 옆에 만든 웹앱을 바로 실행해 보여주는 화면(캔버스·아티팩트)을 제공합니다. 여기서 만들고, 링크를 만들어 학생에게 보내면 끝입니다.

1

도구를 고르고 캔버스·아티팩트를 켭니다

  1. Gemini, ChatGPT, Claude 중 이미 계정이 있는 것을 고릅니다. 셋 다 처음이라면 어느 것이든 좋습니다.
  2. 새 채팅을 열고 위 표를 참고해 캔버스(아티팩트) 기능을 켭니다.
  3. 스마트폰보다는 컴퓨터 브라우저에서 작업하는 것이 훨씬 편합니다.
💡 팁

무료 요금제로도 충분히 만들 수 있습니다. 다만 하루 사용량 제한이 있으니 긴 대화는 한 번에 끝내는 것이 좋습니다.

2

대화로 무엇을 만들지 구체화합니다

가장 중요한 단계입니다. 첫 메시지를 아래처럼 보내고, AI의 질문에 차근차근 답합니다. (핵심 원칙 참고)

첫 메시지 · 복사해서 빈칸만 채우세요
나는 [중학교 2학년] 학생을 가르치는 지구과학 교사야.
[판의 경계를 탐험하는] 교육용 웹앱을 만들고 싶어.

바로 코드를 짜지 말고, 먼저 나에게 질문하면서 무엇을 만들지 충분히 구체화한 다음에 코드를 짜줘.
대상 학생, 학습 목표, 핵심 기능, 화면 구성, 사용 기기 등 네가 알아야 할 것을 한 번에 5~6개씩 질문해 줘.
기획이 정리되면 요약을 보여주고 내 확인을 받은 뒤에 코드를 짜줘.
  • AI 질문에 모두 답하지 않아도 됩니다. 모르는 것은 "네가 추천해 줘"라고 답하세요.
  • AI가 보여준 요약을 꼼꼼히 읽고, 다르게 이해한 부분은 바로잡아 줍니다.
3

"이제 코드를 짜줘" · 미리보기 확인

요약이 마음에 들면 코드 생성을 요청합니다. 오른쪽 캔버스·아티팩트 화면에 웹앱이 바로 실행되어 나타납니다.

코드 요청
좋아, 정리한 내용대로 이제 코드를 짜줘.
HTML 파일 하나에 CSS와 JavaScript를 모두 넣어서 만들어줘. 외부 로그인이나 서버 없이 브라우저에서 바로 실행되어야 해.
스마트폰과 태블릿에서도 잘 보이게 만들어줘.
  • 미리보기에서 학생처럼 직접 눌러 봅니다. 버튼, 퀴즈, 애니메이션이 의도대로 동작하는지 확인합니다.
  • 과학적 내용(용어, 방향, 수치)이 정확한지 교사의 눈으로 검토합니다. AI는 그럴듯하게 틀릴 수 있습니다.
4

수정을 요청합니다 (구체적으로, 한 번에 하나씩)

마음에 안 드는 부분을 어디가 · 어떻게 형태로 말합니다. "더 좋게 해줘"보다 "퀴즈 정답을 고르면 초록색으로 표시해 줘"가 훨씬 잘 됩니다.

수정 요청 예시
다음 세 가지를 수정해 줘. 다른 부분은 그대로 유지해.
1. 수렴 경계 단면도에서 해양판이 대륙판 아래로 섭입하는 방향이 반대야. 고쳐줘.
2. 퀴즈에서 정답을 고르면 초록색, 오답이면 빨간색으로 표시하고 간단한 해설을 보여줘.
3. 글자 크기를 전체적으로 조금 키워줘. 교실 TV에서 보기 편하게.
⚠️ 수정이 꼬이기 시작하면

여러 번 고치다 이상해지면 "지금까지 정리한 기획을 바탕으로 처음부터 다시 깔끔하게 만들어 줘"라고 요청하세요. 대화로 구체화해 둔 기획이 있으니 금방 다시 만들어 줍니다.

5

링크를 만들어 학생에게 공유합니다

  1. 아티팩트 화면 우측 상단의 공유(또는 게시 Publish) 버튼을 누릅니다.
  2. 게시를 선택하면 누구나 열 수 있는 공개 링크가 만들어집니다.
  3. 링크를 복사해 학급 게시판, 카카오톡, QR코드로 공유합니다.
  1. 채팅 화면 상단의 공유 버튼을 누릅니다.
  2. 링크 만들기를 눌러 대화 링크를 복사합니다. 링크를 연 사람은 캔버스 내용을 볼 수 있습니다.
  3. 공유가 어렵다면 캔버스 우측 상단 메뉴에서 코드를 다운로드해 방법 2로 배포합니다.
  1. 캔버스 화면 우측 상단의 공유 버튼을 누릅니다.
  2. 공개 링크를 만들어 복사합니다.
  3. 공유가 어렵다면 캔버스 코드를 복사해 방법 2로 배포합니다.
⚠️ 학생에게 보내기 전에 꼭 확인

내 계정에서 로그아웃한 브라우저(또는 시크릿 창, 스마트폰)로 링크를 열어 보세요. 로그인 없이 열리는지, 학생 기기에서 잘 보이는지 확인한 뒤 공유합니다. 학생이 열 수 없다면 방법 2로 배포하면 확실합니다.

🎉 완성!

QR코드 생성 사이트에 링크를 넣어 QR을 만들면 학생들이 스마트폰으로 바로 접속할 수 있습니다.

📁 GitHub란?

대화로 무엇을 만들지 구체화합니다

방법 1과 완전히 같습니다. 캔버스·아티팩트를 켜지 않고 일반 채팅으로 해도 됩니다. 핵심 원칙의 첫 메시지를 보내고, AI의 질문에 답하며 기획을 정리하세요.

첫 메시지
나는 [중학교 2학년] 학생을 가르치는 지구과학 교사야.
[판의 경계를 탐험하는] 교육용 웹앱을 만들고 싶어.

바로 코드를 짜지 말고, 먼저 나에게 질문하면서 무엇을 만들지 충분히 구체화한 다음에 코드를 짜줘.
대상 학생, 학습 목표, 핵심 기능, 화면 구성, 사용 기기 등 네가 알아야 할 것을 한 번에 5~6개씩 질문해 줘.
기획이 정리되면 요약을 보여주고 내 확인을 받은 뒤에 코드를 짜줘.
2

코드를 만들고 내 컴퓨터에 index.html로 저장합니다

코드 요청 · 파일 하나로
좋아, 정리한 내용대로 이제 코드를 짜줘.
index.html 파일 하나에 HTML, CSS, JavaScript를 모두 넣어서 만들어줘.
서버나 로그인 없이 브라우저에서 바로 열리는 정적 웹페이지여야 하고, 스마트폰에서도 잘 보이게 해줘.
완성된 코드 전체를 하나의 코드 블록으로 보여줘.
  1. AI가 보여준 코드 블록 우측 상단의 복사 버튼을 누릅니다. (캔버스·아티팩트라면 다운로드 메뉴를 써도 됩니다.)
  2. 컴퓨터에서 메모장(Windows) 또는 텍스트 편집기(Mac)를 열고 붙여넣습니다.
  3. 다른 이름으로 저장 → 파일 이름을 정확히 index.html로, 인코딩은 UTF-8로 저장합니다. (메모장에서 파일 형식을 '모든 파일'로 바꿔야 .txt가 붙지 않습니다.)
  4. 저장한 파일을 더블클릭하면 브라우저에서 열립니다. 잘 동작하는지 확인합니다.
💡 왜 파일 하나로 만드나요?

파일이 하나면 GitHub에 올리고 관리하기가 가장 쉽습니다. 파일 이름이 index.html이어야 주소만 입력해도 그 페이지가 열립니다. 한글이 깨지면 "UTF-8로 저장했는지" 먼저 확인하세요.

3

GitHub에 저장소를 만들고 파일을 올립니다

  1. github.com에 로그인하고, 우측 상단 ＋ → New repository를 누릅니다.
  2. Repository name에 영문 이름을 입력합니다. 예: plate-boundary-app (띄어쓰기 대신 - 사용)
  3. Public을 선택하고 Create repository를 누릅니다. 다른 설정은 건드리지 않아도 됩니다.
  4. 새 저장소 화면에서 uploading an existing file 링크를 누릅니다.
  5. 2단계에서 저장한 index.html을 드래그해서 놓습니다.
  6. 아래 Commit changes 버튼을 누릅니다. 이제 코드가 GitHub에 저장되었습니다.
ℹ️ 커밋(commit)이란?

"이 상태로 저장" 버튼입니다. 파일을 올리거나 고칠 때마다 커밋을 하며, 모든 커밋 이력이 남아 언제든 이전 버전으로 돌아갈 수 있습니다. 이것이 버전 관리입니다.

4

Vercel에 연결하고 배포합니다

  1. vercel.com에서 Sign Up → Continue with GitHub로 가입·로그인합니다. (개인 사용은 Hobby 무료 요금제)
  2. 대시보드에서 Add New… → Project를 누릅니다.
  3. GitHub 저장소 목록에서 방금 만든 저장소 옆 Import를 누릅니다. 목록에 없으면 Adjust GitHub App Permissions로 접근 권한을 허용합니다.
  4. 설정 화면은 아무것도 바꾸지 않고 Deploy를 누릅니다. (Framework Preset은 'Other'로 두면 됩니다.)
  5. 1분 정도 기다리면 🎉 축하 화면과 함께 주소가 나옵니다. Visit을 눌러 확인하고, 주소를 복사합니다. 예: https://plate-boundary-app.vercel.app
💡 주소를 예쁘게 바꾸려면

Vercel 프로젝트의 Settings → Domains에서 원하는이름.vercel.app으로 바꿀 수 있습니다. (이미 누가 쓰는 이름은 안 됩니다.)

🎉 완성!

이 주소는 계속 유지됩니다. 학생, 동료 교사 누구나 로그인 없이 열 수 있습니다. QR코드로 만들어 수업 자료에 넣어 두세요.

5

수정하기 · 고치면 자동으로 다시 배포됩니다

수업하다 보면 고칠 것이 생깁니다. 처음부터 다시 할 필요 없이 파일만 바꾸면 됩니다.

  1. AI 채팅으로 돌아가 수정을 요청합니다. "다른 부분은 그대로 두고 ○○만 고쳐서, 전체 코드를 다시 보여줘."
  2. 새 코드 전체를 복사합니다.
  3. GitHub 저장소에서 index.html을 클릭 → 우측 상단 ✏️ (Edit) 연필 아이콘을 누릅니다.
  4. 기존 내용을 전체 선택(Ctrl+A)해 지우고 새 코드를 붙여넣습니다.
  5. Commit changes… → 무엇을 바꿨는지 짧게 적고(예: "퀴즈 해설 추가") → Commit changes.
  6. Vercel이 변경을 감지해 자동으로 다시 배포합니다. 1분 뒤 같은 주소를 새로고침하면 반영되어 있습니다.
⚠️ 바뀐 게 안 보여요

브라우저가 이전 화면을 기억하고 있을 수 있습니다. Ctrl+Shift+R(강력 새로고침) 또는 시크릿 창으로 열어 보세요. Vercel 대시보드의 Deployments에서 배포 상태가 Ready인지도 확인합니다.

C
Codex (ChatGPT)
자동화 지원

ChatGPT의 코딩 에이전트입니다. GitHub 저장소를 연결하면 요청한 수정을 코드로 만들어 반영해 줍니다. 마찬가지로 Vercel이 자동 배포합니다.

ℹ️ 언제 넘어가면 좋을까요?

파일이 여러 개로 늘어나거나, 수정이 잦아지거나, 여러 앱을 관리하게 될 때입니다. 처음에는 방법 2의 5단계까지로 충분합니다. 여기서도 원칙은 같습니다. "바로 코드를 짜지 말고, 먼저 나와 대화해 줘."

자주 겪는 문제

🔍 주소를 열면 404 NOT FOUND

파일 이름이 정확히 index.html인지 확인하세요. index.html.txt, Index.html, index.htm은 안 됩니다. 저장소 첫 화면(최상위)에 파일이 있어야 합니다.

⬜ 화면이 하얗게만 나와요

코드가 일부만 복사됐을 가능성이 큽니다. 코드 마지막이 </html>로 끝나는지 확인하고, AI에게 "전체 코드를 처음부터 끝까지 다시 보여줘"라고 요청하세요.

🈳 한글이 깨져요

파일을 UTF-8로 저장했는지 확인하세요. 코드 상단에 <meta charset="UTF-8">이 있는지도 확인합니다.

🤔 오류 메시지를 모르겠어요

오류 화면을 캡처해서 AI에게 붙여넣고 "이 오류가 왜 나는지 설명하고 고쳐줘"라고 하세요. 대부분 바로 해결됩니다.

네. 이 가이드의 모든 단계는 코드를 읽거나 쓰지 않습니다. 복사·붙여넣기와 버튼 클릭만 합니다. 중요한 것은 코드 지식이 아니라 "무엇을 만들지" 명확히 말하는 능력이고, 그것은 교사가 가장 잘하는 일입니다.
어떤 AI가 가장 좋은가요?
셋 다 교육용 웹앱을 만들기에 충분합니다. 이미 쓰고 있는 것을 쓰세요. 결과가 마음에 안 들면 같은 기획 요약을 다른 AI에 붙여넣어 비교해 보는 것도 좋은 방법입니다.
무료로 가능한가요?
네. AI 채팅 무료 요금제, GitHub 무료, Vercel Hobby(개인·비상업) 무료로 모두 가능합니다. AI 무료 요금제는 사용량 제한이 있어 긴 작업은 나눠서 하는 것이 좋습니다.
학생 개인정보는 괜찮나요?
이 가이드의 방식은 로그인 없이 브라우저에서만 실행되는 웹앱이므로 학생 정보가 어디에도 저장되지 않습니다. 학생 이름·점수를 저장하는 기능을 추가하려면 별도 검토가 필요하니, 처음에는 저장 기능 없이 만드세요.
AI가 만든 내용이 과학적으로 틀릴 수도 있나요?
네, 그럴듯하게 틀릴 수 있습니다. 반드시 교사가 직접 검토하세요. 프롬프트 모음의 "⑤ 과학적 검토 요청"을 쓰면 AI 스스로 점검하게 할 수도 있지만, 최종 확인은 교사의 몫입니다.
방법 1로 만든 것을 나중에 방법 2로 옮길 수 있나요?
네. 캔버스·아티팩트에서 코드를 다운로드(또는 복사)해 index.html로 저장한 뒤, 방법 2의 3단계부터 진행하면 됩니다.
동료 교사와 같이 수정하고 싶어요
GitHub 저장소의 Settings → Collaborators에서 동료의 GitHub 계정을 추가하면 함께 파일을 수정할 수 있고, 누가 무엇을 바꿨는지 이력이 남습니다.
손그림이나 캡처 화면도 보여줄 수 있나요?
네. 원하는 화면 구성을 종이에 그려 사진을 찍거나, 참고할 사이트를 캡처해 채팅에 첨부하면 훨씬 정확하게 만들어 줍니다. "이 그림처럼 배치해 줘"라고 말하세요.
